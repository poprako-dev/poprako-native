# Local Translator Model

本文定义首期本地 Translator 的领域模型、数据含义和功能边界，供后续数据结构、用例、交互与测试设计使用。术语见 [CONTEXT.md](../CONTEXT.md)，工程约束见 [REQUIREMENTS.md](./REQUIREMENTS.md)。

迁移能力、搜索行为和规模/响应目标见[迁移能力与验收目标](./contract/migration-acceptance.md)。

模型字段、时间、空态、数值类型、表关系和事务约束见[模型与持久化契约](./contract/model-representation.md)；本文定义领域含义。

本文定义目标行为；字段名表达模型语义，不直接规定存储表或传输协议。

保存时机、在途编辑、失败与正常退出见[编辑保存与离开行为](./contract/editor-save.md)。

图片格式、显示资源、像素保护、内存预算和任务恢复见[图片资源与长任务契约](./contract/image-lifecycle.md)。

## 1. 产品边界

交换协议、用例 IPC、偏好默认值、工程门禁与分阶段实施顺序统一见 [IMPLEMENTATION.md](./IMPLEMENTATION.md)；该方案不改变本文已确认的领域边界。

- 核心关系为 `comic → page → unit`。一个 comic 可以有零到多个 page，一个 page 可以有零到多个 unit。
- 本地 comic 是独立翻校项目，对应服务端 chapter。不另设 project、chapter 或服务端 comic 对应的上层实体。
- home、comic detail、translator 是同一套模型的三个入口，不分别维护权威数据副本。
- 应用完全离线。图片导入后复制到应用管理目录，后续操作不依赖原文件仍然存在，也不依赖远程图片地址。
- 首期单窗口，逐个编辑 comic；切换项目前处理当前编辑的保存，不支持多个窗口并发编辑。
- 保留 Web translator 的核心翻校能力，移除成员权限、任务分配、workflow 和术语库。模式是操作方式，不是权限或阶段状态。
- 不建设在线同步、回收站、版本历史或跨会话撤销；文件交换不承担多方修改的自动合并。

## 2. 核心模型

### 2.1 Comic

| 字段 | 含义与约束 |
| --- | --- |
| `id` | 本机生成的稳定身份，不依赖标题、列表位置或导入文件中的外部身份 |
| `title` | 必填的项目标题，不允许空白标题 |
| `subtitle` | 可留空副标题，未填写时为空字符串 |
| `author` | 可留空作品作者，未填写时为空字符串；不代表本机使用者或翻译贡献者 |
| `created_at` | 创建时间 |
| `updated_at` | 内容修改时间，与最近打开时间分离 |

- 不保存独立的翻译完成、校对完成或 workflow 字段。进度从所属单元内容计算。
- 封面使用当前第一页图片，不提供独立封面选择或上传。页面为空时显示占位封面。
- 删除最后一页后保留 comic 资料；空 comic 可以重新添加图片，不能进入 translator，也不能因为没有待处理单元就视为完成。

### 2.2 Page

| 字段 | 含义与约束 |
| --- | --- |
| `id` | 稳定的页面身份，重排或换图不改变 |
| `comic_id` | 唯一所属 comic |
| `index` | comic 内从零开始的连续顺序号 |
| `image` | 当前图片信息，包含受管文件引用、原始文件名、格式、宽度与高度 |
| `created_at` | 创建时间 |
| `updated_at` | 内容修改时间 |

- 图片文件名、受管文件引用、页码和页面身份分别表达不同含义，不得互相替代。
- 创建或导入成功的 page 必须配有可用的本地图片。后续图片意外丢失或不可读属于资源异常，仍保留页面和译文，并明确指出问题。
- 图片作为 page 的组成部分，首期不增加独立的图片资产管理实体。缩略图和预览图可以重建，不是用户原图或页面身份的替代品。
- 页面属于一个 comic，不因图片内容相同而自动合并页面。
- 首期接收静态 JPEG、PNG、WebP、BMP；单图总像素最多 32,000,000，最长边最多 16384，导入或压缩前均检查。文件大小不代替像素和解码内存校验。
- 大于 50 MiB 的图片使用 WebP 显示副本，原图按字节复制并保留，含图导出仍使用原图；预览和原始分辨率显示图块不能替代原图。50 MiB 不是直接拒绝导入的文件大小上限。
- 页面宽高及标记坐标采用统一方向校正后的显示空间，原图字节与方向元数据不改写；交换文件的坐标映射遵守这一规则。

### 2.3 Unit

| 字段 | 含义与约束 |
| --- | --- |
| `id` | 稳定的单元身份，编辑和重排不改变 |
| `page_id` | 唯一所属 page |
| `index` | page 内从零开始的连续顺序号 |
| `x_coord` / `y_coord` | 图片上的归一化位置，范围为 `[0, 1]`，不是屏幕坐标 |
| `is_bubble` | 是否为框内文本；否则为框外文本 |
| `is_flagged` | 是否标记为需要后续关注，独立于文本和校对状态 |
| `translated_text` | 可留空翻译文本，未填写时为空字符串 |
| `proofread_text` | 可留空校对文本，未填写时为空字符串 |
| `is_proofread` | 独立的校对确认状态 |
| `created_at` | 创建时间 |
| `updated_at` | 内容修改时间 |

- unit 是带位置的标记，不要求增加矩形范围、原文转录或 OCR 数据。
- 允许只有校对文本、没有翻译文本，也允许只有标记而尚无任何文本。
- 修改或清空校对文本不得隐式修改 `is_proofread`；切换确认状态不得隐式填充或清空文本。修改翻译文本也不自动重置校对确认。
- 最终文本取非空校对文本，否则取非空翻译文本；两者都无内容时没有最终文本。不另外持久化 `final_text`，也不要求已确认校对才能使用校对文本。
- 重排只改变所属页内顺序。首期不照搬服务端用于并发保存的单元链、隐藏删除节点或贡献者权限模型。

### 2.4 身份、顺序与派生统计

- ID 与顺序分离。同一父对象内的顺序号连续且不重复，增删和重排共同维护这一约束。
- comic、page、unit 的本机身份统一使用随机 UUID v4 字符串，创建后保持稳定；不从标题、时间或顺序推导身份。
- 导入为新 comic 时生成新的本机身份。同一文件可以导入为两个独立项目，修改或删除其中一个不影响另一个。
- 新导入 comic 及所属 page/unit 的创建与修改时间使用本次本地创建时间，不继承文件中的来源时间；已有 comic/page 的创建时间不因替换整页单元而改变。
- 替换已有页的翻校内容时保留该 page 身份，为导入的单元分配本机身份；不根据外部 unit ID 合并记录。
- 页数由 page 集合计算；总单元数由 unit 集合计算；翻译数按翻译文本是否有内容计算；校对数按 `is_proofread` 计算；标记数按 `is_flagged` 计算。
- 只有校对文本的单元可以具有最终文本，但不因此计入翻译文本数。文本差异、校对改动及校对补充等统计从双阶段内容推导。
- 不把计数、百分比或最终文本作为另一份可独立编辑的业务事实。零分母不推导出百分之百完成。

### 2.5 空文本与内容修改

- 副标题、作者、翻译文本和校对文本统一以空字符串表达未填写，不同时使用 `null` 和空字符串表达同一状态。
- 标题、副标题和作者保存时去除首尾空白、保留中间内容；处理后标题为空则拒绝，副标题和作者为空则保存为空字符串。
- 翻译或校对文本只含空格、制表符、换行等空白时，保存和导入都规范为空字符串；含实际文字的正文保留原有缩进、空格和换行。文本存在性、最终文本和统计使用同一规则。
- 内容修改逐级更新所属对象的 `updated_at`。修改 unit 的文本、位置、框内外类别、关注或校对确认时，同时更新该 unit、所属 page 和 comic 的内容修改时间。
- 最近打开时间和工作位置属于本机工作状态；浏览、切换编辑模式不修改内容时间。

## 3. 本机工作状态与偏好

### 3.1 工作位置

每个 comic 保存最近打开时间、上次 page ID、上次 unit ID 和上次编辑模式，用于 home 的最近项目与继续工作入口。

- 使用身份定位，不使用旧页码或旧单元序号定位；重排后仍继续同一页面和单元。
- 所记单元删除后清除该单元定位；所记页面删除后回退到仍存在的第一页。没有页面时回到 comic detail。
- 编辑模式为翻译、校对、只读，三者自由切换；没有既有工作位置时默认从第一页的翻译模式进入。
- 浏览行为可以更新最近打开时间，不应仅因打开项目就表示翻校内容发生修改。

### 3.2 应用偏好

可配置快捷键、特殊字符及其收藏和顺序、重定位和标记透明度等设置属于本机应用偏好，不附属于某个 unit，也不引入 user 或成员实体。界面固定浅色，不持久化主题选择。

本机工作位置与应用偏好默认不随项目导出。持久化遵守 Rust 集中处理的工程边界，不直接移植参考 Web 的 `localStorage` 作为另一套业务存储。

## 4. 操作入口与生命周期

| 入口 | 首期能力 |
| --- | --- |
| home | 创建、导入、浏览和删除 comic，继续最近工作 |
| comic detail | 编辑项目资料，查看页面和进度，增加、删除、重排页面，换图，导入译文，导出 ZIP |
| translator | 翻译／校对／只读模式，标记增删与移动、框内外切换、单元重排、翻校编辑、标记筛选、差异查看、搜索替换、快捷键、特殊字符和保存 |

- translator 使用本地原图与本地预览资源，保留画布浏览、定位、翻页和对应单元交互。
- 自动保存只使用一个可重置定时器，停止内容编辑 15 秒后触发；持续编辑会延后，不另设周期或最迟保存定时器。手动保存和翻页、离开、正常退出前立即处理待保存修改。
- 保存失败保留当前页面与输入，允许重试、取消离开或明确放弃未保存修改后离开；已经成功保存的内容不会被撤销。保存结果未确认时先核实，不把请求失败当作已回滚。
- 首期异常退出后只恢复最近成功保存的内容，不另建跨重启草稿恢复；未提交的内存编辑可能丢失，不能承诺只丢固定秒数的内容。
- 当前页保存采用完整单元集合，筛选不缩小保存范围；保存期间继续编辑的内容不得被旧回执覆盖。正常退出的保存协调不能作为强制终止或崩溃时的保存保证。
- 搜索替换在当前 comic 的翻译或校对文本范围内工作，不跨项目隐式修改内容；替换文本仍遵守校对确认独立的规则。
- 换图前预览新图片，明确选择保留或清空该页 unit。保留时 page / unit 身份、文本与归一化坐标不变，不自动猜测新的标记位置；清空时移除该页全部 unit。
- 删除 comic、page 或 unit 前明确确认。删除父对象同时删除其所属内容，只清理该对象拥有的受管资源，不删除用户原始导入目录中的文件。
- 首期不提供回收站、版本历史或跨会话撤销，不能依赖这些未实现能力解释删除操作的可恢复性。

## 5. 导入与页序

### 5.1 来源与完整性

- 支持图片文件夹、LP TXT、PRK JSON，以及本应用导出的 ZIP。译文 ZIP 或单独译文没有图片时，需要另行选择图片目录。
- 文件夹导入只读取当前层的图片，不递归子目录，忽略非图片文件。
- 从译文创建 comic 前必须配齐所有图片，译文页面总数与图片总数必须一致，不允许先创建缺图页面再补图。
- 导入已有 comic 时，译文页面总数与当前 comic 页面总数必须一致；已有图片异常需要先解决，不能借导入绕过配图要求。
- 展示页面对应关系与处理方式的预览，确认后整体应用。解析、配图、准备资源或写入失败时，不留下可见半项目，不部分覆盖已有翻校内容。

### 5.2 按顺序对应

- LP 按文档中的页面顺序排列；PRK 按明确的页面顺序排列，拒绝重复或不完整的页序。
- 新导入的图片按统一自然数字序排列；已有 comic 使用保存的 page 顺序。双方按位置一一对应，不通过文件名、坐标或外部身份猜测匹配关系。
- 图片总数不一致时拒绝导入，不自动丢弃多余图片或跳过缺失页。页数相同也必须展示预览，不宣称已经验证图片内容对应正确。
- 自然排序只决定初次图片顺序，创建后以保存的 page 顺序为准。后续打开项目不重新扫描原始目录来覆盖页序。

### 5.3 跨平台自然数字排序

Windows 与 macOS 使用同一规则，不取决于当前系统语言、目录枚举顺序或平台默认比较器。

- 文件名中的连续 ASCII 数字按数值比较，因此 `1.png、2.png、10.png` 按此顺序排列；不能因数字过长而溢出并改变排序。
- 数值相同的数字串，较短者优先，例如 `1.png、01.png、001.png`。
- 非数字文字以统一的 Unicode 规范化和小写比较规则处理，不使用平台区域排序。规范化采用 NFC；最终相同的比较结果由原始文件名 UTF-8 字节序打破平局。
- 文件名排序不改变保存的原始名称，不承诺特殊字符等全部细节与各版本 Windows 资源管理器一致。微软明确说明 `StrCmpLogicalW` 的结果可能随系统版本变化，不适合作为固定排序标准。[官方说明](https://learn.microsoft.com/en-us/windows/win32/api/shlwapi/nf-shlwapi-strcmplogicalw)

### 5.4 文本映射与覆盖方式

| 输入 | 本地结果 |
| --- | --- |
| 图片文件夹 | 创建有序页面，各页初始无 unit |
| LP 作为翻译导入 | 单份文本填入 `translated_text`，校对文本为空，`is_proofread` 为否 |
| LP 作为校对导入 | 单份文本填入 `proofread_text`，翻译文本为空，`is_proofread` 为否 |
| PRK 导入 | 保留双阶段文本、独立校对确认和标记，不根据当前编辑模式改写字段含义 |

LP 没有表达的关注标记初始化为否。LP 不推断原译文、贡献者或已经完成校对；PRK 的外部身份不直接作为本机主键。

对已有 comic，提供两种明确的整页处理方式：

- **只填空白页**：只导入当前没有任何 unit 的页面。已有定位标记但文本为空的页面仍跳过。
- **替换整页单元**：用导入页面的全部 unit 替换对应页的全部既有 unit。输入空页也会清空目标页，不合并原有文本或逐单元匹配。

## 6. 导出与离线交接

### 6.1 两种 ZIP

| 类型 | 内容 |
| --- | --- |
| 译文 ZIP | `translation.prk.json` 与 `translation.lp.txt` |
| 含图片 ZIP | 两种译文与全部页面图片，图片放入 `images/` |

- 两种导出都打包为 ZIP，不以单独 TXT 或 JSON 文件替代对应导出入口。
- PRK 承担本地项目资料、有序页面和完整翻校内容的往返保存；与现有 PRK 格式的映射属于边界适配，不把服务端 comic / chapter 两级直接引入本地模型。
- 保留现有 PRK 可识别的翻校内容；本地资料及图片引用的表达在后续交换协议中明确。PRK 往返完整性指项目资料、页序与翻校内容；本机身份和创建／修改时间在重新导入时新建，不承诺恢复服务端成员权限、workflow 或外部身份。
- LP 每个 unit 只输出最终文本，并保留相应位置、顺序和框内外类别。它不能完整表达双阶段文本、校对确认和关注标记，不作为完整往返保存格式。
- 同一 ZIP 含两种译文时，重新导入以 PRK 为内容来源，不重复导入 LP，也不把损坏 PRK 静默降级为有损 LP 导入。
- 包含全部图片的项目包可以离线交给另一台电脑继续编辑，不包含本机工作位置、应用偏好和不存在的编辑历史。

### 6.2 图片编号与配套使用

- 按当前 page 顺序，从一开始统一编号图片，最少三位，不足补零；总页数超过三位时统一扩展位数。例如 `001.png、002.jpg`，保留对应图片格式。
- LP 图片引用与 PRK 图片路径同步使用导出名称；含图片包中的实际名称必须一致。导出不修改本机页面身份、受管图片或保存的原始文件名。
- 译文 ZIP 同样使用这套编号。与外部图片配套使用时，接收方必须采用相同页序和编号，不能假设 LP 仍引用原始文件名。
- 页面重排后再导出的含图片包，按自然数字序导入仍应恢复当前页序，不能重新回到原始图片顺序。

### 6.3 一致性与失败

- 导出前保存当前待保存修改，保存失败则停止导出。导出采用一致的内容快照，避免页序、单元和图片来自不同状态。
- 含图片 ZIP 必须包含所有页面图片；任何一页受管图片丢失或不可读，整次导出失败，并指出问题页，不将不完整包报告为成功。
- 图片异常不阻止另行导出译文 ZIP，不删除项目内容。
- 失败或取消产生的临时文件不作为完成的 ZIP 交付；数据库提交与文件副作用分别遵守工程规范的失败语义。

## 7. 模型验收场景

以下是行为验收依据。

| 场景 | 应有结果 |
| --- | --- |
| 同一文件导入两次 | 各自生成本机身份和创建／修改时间，编辑或删除互不影响 |
| 保存标题与可留空资料 | 去除资料首尾空白，空白标题被拒绝，可留空资料使用空字符串 |
