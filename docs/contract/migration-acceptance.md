# 首期迁移能力与验收目标

本表将 [MODEL.md](../MODEL.md) 的能力范围连接到可观察的验收场景。界面来源见[界面来源](./ui-reference.md)。

## 已定能力与验收入口

| 能力 | 迁移责任 | 用户可观察的验收依据 |
| --- | --- | --- |
| 项目创建与浏览 | 旧 Native 仅作页面组织参考；本地持久化需实现 | 创建后能在 home 找到 comic，退出后再次打开资料仍存在 |
| 导入并管理本地图片 | 本地实现 | 导入成功后移动原始目录，页面仍能使用受管图片 |
| 项目资料与封面 | 本地实现 | 可修改标题、副标题和作者；封面随当前第一页改变；空 comic 显示占位 |
| 继续工作 | 按稳定身份改写旧 Native 页序号记录 | 重排后继续同一 page / unit；对象删除后的回退遵守 MODEL.md |
| 页面增加、删除与重排 | 本地实现；不依赖 Web 单页删除占位接口 | 页面身份稳定、页序连续；删除最后一页后项目仍可管理和重新加图 |
| 换图 | 本地实现 | 明确选择保留或清空单元；保留时身份、文本及归一化坐标不变 |
| 画布浏览与定位 | 参考 Web 几何和交互 | 缩放、平移、翻页与定位能对应正确页面及标记；窗口缩放不改变保存坐标 |
| 标记增删与移动 | 参考 Web 交互，改写持久化与删除确认 | 新增或移动后保存正确位置；删除需确认，包括没有文本的标记 |
| 框内外切换 | 参考 Web 交互 | 类别可切换，位置和双阶段文本保持原意 |
| 单元重排 | 参考 Web 数组/拖动行为，替换在线链式保存 | 重排后身份和文本不变，顺序连续；画布与列表显示对应一致 |
| 三种编辑模式 | 替换在线权限和 workflow 判定 | 翻译、校对和只读自由切换；只读不允许修改内容；能够退出只读 |
| 双阶段文本与校对确认 | 参考 Web 能力，移除贡献者耦合 | 翻译、校对和确认状态独立；修改文本不隐式改变确认状态 |
| 复制翻译到校对 | 保留 Web 已有作用范围 | 仅给当前 unit 的空校对文本填入译文，不覆盖已有校对、不改变确认状态 |
| 整页校对确认／取消 | 保留 Web 整页作用范围 | 校对模式下明确作用于当前页全部 unit，包括无文本单元；只变确认状态，不修改文本；列表筛选不隐式缩小范围 |
| 关注标记与筛选 | 标记参考 Web；筛选补足现有缺口 | 可关注或取消关注；当前页单元列表可筛选关注标记，页面导航显示各页关注数量 |
| 差异与进度 | 参考 Web 差异计算，统计改为本地派生 | 正确呈现双阶段差异与统计；空页或只有校对文本不产生虚假翻译完成率 |
| 搜索替换 | 对齐 server 搜索/替换行为，查询及修改改走 Rust | 当前 comic 的选定文本阶段采用大小写敏感的字面子串匹配；一个单元多处命中只算一条结果，替换全部不重叠匹配；超出 100 个命中单元明确报错；校对确认不受替换影响 |
| 快捷键与特殊字符 | 参考 Web 操作，改为本机偏好 | 核心操作可用键盘；特殊字符可配置、收藏和排序；偏好在重启后保留 |
| 保存与离开页面 | 参考 Web 协调语义，本地用例重新实现 | 自动、手动和离开前保存可用；失败保留编辑并明确提示；具体机制见[保存契约](./editor-save.md) |
| 译文导入 | 参考解析逻辑，处理实际格式差异 | 页数和配图完整；LP 导入阶段明确；PRK 保留其携带的双阶段内容；整体应用或失败保留原内容 |
| 两种 ZIP 导出 | 本地实现完整内容快照与文件交付 | 按当前页序编号；两种译文都在包内；含图导出任一图片不可读则整体失败 |
| 项目删除 | 本地实现 | 确认后删除所属数据和受管资源，保留用户原始导入文件；不依赖回收站或历史恢复 |

## 使用规模与验收范围

以下为已确认的使用规模与验收档位。

| 维度 | 已知使用范围 |
| --- | --- |
| 一个 comic 的常见页数 | 20～80 页 |
| 用户实际规模的页数上沿 | 不超过 200 页，作为验收范围，不是产品硬上限 |
| 每页 unit 数量 | 约 10～100 个 |
| 单张图片文件大小 | 200 KiB～50 MiB |
| 图片宽高 | 用户实际范围未提供；已定接收保护为总像素 ≤32,000,000、最长边 ≤16384 |
| 性能验收机器档位 | 8 GB 内存＋SSD |

200 页、每页约 100 个 unit、单图 50 MiB 用于界定验收规模，不单凭这些数字拒绝导入或编辑。图片解码与内存限制已由[图片资源契约](./image-lifecycle.md)明确；超过 50 MiB 使用 WebP 显示副本并保留原图；不由此承诺任意超大图片或任意规模都可安全处理。

组合上沿为 200 页 × 每页 100 个 unit，共 20,000 个 unit；若每张图片均取 50 MiB，文件合计约 9.77 GiB。该推导用于压力样例设计，不代表典型项目或已确认的全量图片夹具，文件体积也不代表解码内存。具体样例结合[图片资源契约](./image-lifecycle.md)确定的图片尺寸，由[验收与交付要求](../IMPLEMENTATION.md#6-验收与交付)固定并记录。

## 响应目标

在 8 GB 内存＋SSD 档位的机器上，采用以下目标；CPU、系统、WebView、数据样例、计时起止点和采样方式由[验收与交付要求](../IMPLEMENTATION.md#6-验收与交付)落实。

| 场景 | 目标 |
| --- | --- |
| 普通输入、选择等交互 | 100 ms 内反馈 |
| 已缓存页面切换 | 300 ms 内完成 |
| 打开已有普通项目 | 2 秒内可开始操作 |
| 首次大图解码、导入和导出 | 单独测量，保留长任务反馈，不套用上述固定时限 |
| 内存预算 | Rust＋WebView 稳定目标 ≤1 GiB、解码／导入峰值目标 ≤1.5 GiB；分项与统计口径见资源契约，待实测 |

已有项目打开的目标不等于所有原图完成解码；后台仍在进行的工作必须如实呈现。响应目标是后续验收依据，当前没有性能实测结果。
