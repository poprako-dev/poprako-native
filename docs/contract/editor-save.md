# 编辑保存与离开行为

本文承接[模型与持久化契约](./model-representation.md)，定义完整快照、15 秒单一定时器、在途编辑、离开与退出行为。异常退出只恢复已提交内容。

## 1. 草稿、保存基线与提交

- 每次编辑会话绑定一个 comic 和 page；当前页的完整单元集合只有一份可编辑草稿。筛选、选中、折叠和只读展示不另建权威集合，提交不能只包含当前可见单元。
- 当前页单元集合必须完整加载后才允许按快照编辑与保存；可以虚拟化渲染，但不能将部分加载的数据误作全量快照。其他页面及图片仍按需加载。
- 草稿单元只包含编辑所需字段，不伪造创建／修改时间。前端创建标记时一次性生成最终 UUID v4；Rust 校验格式、所属范围与主键冲突，首次提交成功时生成时间。保存不更换单元身份。
- 保存基线是最近一次经 Rust 确认的完整页单元内容及其保存版本。dirty 由规范化后的草稿与基线比较得出；焦点、模式、筛选及工作位置变化不产生内容脏状态。
- 提交一份固定、完整、有序的当前页单元快照。数组表达顺序，包含 ID、坐标、类别、关注、双阶段文本及校对确认；不允许编辑父级、创建时间或派生统计。
- Rust 在一个事务内验证版本及集合，计算新增、删除、字段和顺序差异，只写实际变化。未出现在完整目标集合的已有 unit 被删除；不能把分页结果或筛选结果当作完整目标集合。
- 新 unit ID 不得已经属于其他页面，也不能通过通用 upsert 改写其他对象。父级身份和页是否仍存在都由 Rust 校验。
- 完整快照的范围是单页，不是整个 comic。参考 server 的普通保存 100 条拆批不沿用为本地单页硬上限；已有搜索替换的批量限制仍按迁移决定执行。

## 2. 保存版本与结果确认

- page 增加内部持久化字段 `unit_revision`：非负整数、初始为 0。它只用于单元集合的写入校验，不作为业务进度，也不进入项目交换文件。
- `unit_revision` 使用 Rust `i64`、SQLite `INTEGER` 和生成的安全整数 `number`，上界为 JavaScript 最大安全整数；增长使用受检查运算，不能回绕或转为浮点数。
- 每次单元集合实际变化时在同一事务内增加一次版本；自动／手动保存、批量替换、校对操作、整页内容导入和换图清空单元都走同一规则。纯页序、图片保留换图和工作位置不改变单元版本。新导入页面以完整初始内容和版本 0 创建。
- 保存请求携带读取基线的版本。Rust 在事务内重新检查；版本不符则返回冲突并保留草稿，不把旧快照覆盖到新内容上，不自动把请求版本改成最新后强行重试。
- 相同规范化内容不更新版本、unit/page/comic 的内容时间。实际变化按模型契约逐级更新时间；版本与内容在同一事务提交。
- 成功回执包含提交后的规范化单元内容、版本和新建对象时间，足以更新保存基线。不能只返回成功标志，再靠一次可能失败的刷新才能确认究竟保存了什么。
- 失败明确区分“已知未提交”“提交成功但后续刷新失败”和“提交结果尚未确认”。错误名称及 IPC 形态见 [IMPLEMENTATION.md](../IMPLEMENTATION.md#3-用例和-ipc)，界面不能把它们都显示成未保存。
- 结果尚未确认时保留固定在途快照，先等待原生写入完成并经同一写入协调器读取已提交状态，不并发重发。状态与该快照相同则确认保存；版本和内容仍为旧基线时可重试原请求；其他状态按冲突处理。
- 此处快照相同指 ID、有序集合及全部可编辑字段经过同一规范化后相同，不比较前端没有权威值的时间。不能仅凭版本增加或父级时间变化断定本次请求成功。
- 不以 Promise 超时、组件卸载或取消等待推断 SQLite 回滚。确认结果前不把“放弃”解释为撤销可能已经提交的内容。

## 3. 在途编辑与串行调度

- 每个编辑会话至多一个在途保存。控制器保留已确认基线、当前草稿和固定在途快照；后续保存触发合并为一次待处理请求，不积累每次按键对应的请求队列。
- 普通自动／手动保存期间允许继续输入。回执只确认已发送的那一版；在途期间新增、修改、删除或重排的内容继续保留，不被旧响应覆盖。
- 对回执中的规范化文本：自提交后未再编辑的字段可以接纳规范化值；已再次编辑的字段保持当前草稿，下一次提交再处理。任何情况下不能在输入法组合期间替换输入内容或光标。
- 每次进入页面具有独立会话标识，保存请求和页面加载也有代次。离开后的旧回执不能写入新页面或新会话状态，即使重新打开同一个 page ID 也一样。
- 时间戳不充当请求代次或版本。UI 的保存状态由当前基线、草稿和在途请求推导，不维护会被旧回执随意清零的单一 dirty 布尔值。
- 输入法组合期间不自动提交中间文本；手动保存／离开意图等待组合结束再捕获最终输入，不能中断组合。拖动标记以已完成的交互值进入保存；不在一串 pointermove 中另发并行写入。

## 4. 保存触发

| 触发 | 行为 |
| --- | --- |
| 自动保存 | 只用一个可重置的定时器；最后一次内容编辑结束后等待 15 秒，有实际修改才发起保存 |
| 手动保存／平台保存快捷键 | 立即处理截至触发时的修改；等待已有请求后提交需要补齐的快照，不与它并发 |
| 翻页、离开 translator、切换 comic | 捕获完整编辑值，完成当前页保存后才执行目标动作 |
| 正常关闭窗口或退出应用 | 进入同一离开流程，不能直接让窗口销毁后再尝试保存 |
| 导出、搜索、批量替换、替换页内容或换图 | 先处理相关草稿，再进入对应操作；保存失败时不继续 |
| 没有实际修改 | 不写数据库，不更新修改时间和保存版本 |

- 每次内容编辑重置同一个 15 秒定时器；不增加持续输入期间的最迟保存定时器、固定周期轮询或第二套自动保存计时。持续编辑可以一直推迟自动保存，手动保存和离开前保存不受这 15 秒等待限制。
- 自动保存计时描述发起时机，不承诺磁盘提交在期限内完成。定时器到期而已有请求在途时，只记录一次待处理触发；请求结束后重新检查最新编辑时间、脏状态与会话，再执行保存或用同一定时器等待剩余时间，不无条件补发过期快照。
- 输入法组合、拖动未结束、独占操作或待处理保存错误时不发起自动保存。输入完成后按最终编辑时间安排同一定时器；结束离开、放弃或销毁会话时清理定时器与待处理触发。
- 一次已知保存失败后保留草稿并停止自动重试循环，允许继续编辑，明确显示未保存及重试入口；下一次显式保存或重试使用有效基线与最新草稿。结果不明则先按第 2 节确认。
- 手动保存完成只确认触发时及已纳入请求的内容；若期间继续产生新编辑，界面仍显示待保存状态，不报告当前所有内容均已保存。

## 5. 离开、放弃与加载失败

- 有待保存内容时，离开流程先结束当前组合输入和拖动，随后暂时禁止新的内容编辑，捕获要保存的最终状态并等待提交。重复导航或关闭请求不启动另一套保存；用户取消离开后恢复编辑。
- 用户取消离开并不取消已经进入提交阶段的事务；已确认保存内容保留。之后到达的回执仍按原会话和在途快照处理，不得覆盖取消后新增的输入。
- 保存失败时默认留在原页、保留输入，提供“重试、取消离开、放弃未保存修改并离开”。放弃需要用户明确选择，不能是失败后自动执行或默认选中的退出动作。
- 明确放弃只丢弃尚未确认提交的本次草稿，并停止旧草稿的后续自动保存；已经提交成功或经确认已经提交的内容不被撤销。结果不明时先确认写入状态，不带着仍会落库的旧请求启动新页面编辑。
- 冲突不会触发远端式自动三方合并。保留当前草稿，展示冲突，允许取消操作；需要重新载入时明确按放弃规则处理，不用重新读取覆盖未保存内容。
- 当前页保存成功而目标页加载失败时，保留原页作为可操作页面，显示目标加载错误并允许重试；不能宣称原页保存失败，也不把工作位置提前指向尚未成功进入的目标页。
- 正常窗口关闭、菜单退出及平台退出快捷键共用退出协调流程。强制终止、崩溃、断电以及无法继续执行回调的系统退出不具备关闭前保存保证；不能照搬浏览器 beforeunload 当作桌面实现。
- Tauri 窗口 `onCloseRequested` 可取消关闭，应用级 `ExitRequested` 则需在回调内立即取消本次退出，再异步保存并通过一次已获准退出的状态重新请求退出。菜单／平台快捷键必须明确接入，不能仅监听窗口；不能调用强制销毁或不可取消的重启来绕过未保存处理。[窗口 API](https://v2.tauri.app/reference/javascript/api/namespacewindow/#oncloserequested)、[应用退出 API](https://docs.rs/tauri/latest/tauri/struct.AppHandle.html#method.exit)、[退出与重启源码](https://docs.rs/tauri/latest/src/tauri/app.rs.html#87-94)
- 首期重启只恢复最近成功提交的数据；不新增跨重启草稿表、恢复文件或跨会话撤销。异常退出会丢失尚未提交的内存编辑，持续输入推迟自动保存或已有保存错误时尤其不能承诺只丢固定秒数的内容。

## 6. 搜索、批量修改与结构操作

- 搜索前先保存当前编辑内容，以已提交的 comic 内容搜索；失败则保持弹窗输入但不执行查询。查询结果不包含没有成功保存的内存草稿。
- 批量替换、整页内容替换、换图清空、页删除等操作先保存相关草稿，再暂停该编辑会话接受修改，执行本次操作及必要刷新；完成或明确失败后再恢复可操作状态。
- 搜索结果中的选择必须对应产生结果时的字段与页面版本；执行替换前重新校验。如果内容已经变化，要求刷新结果后重新选择，不能对过期命中范围直接应用。
- 批量替换的全部选定单元在一个数据库事务中完成；每个实际受影响 page 只增加一次单元版本并更新时间，comic 同样按实际变化更新时间。任一校验或写入失败则全部回滚，不留下部分替换。
- 搜索及替换的匹配、次数限制和确认状态独立性沿用[迁移能力与验收目标](./migration-acceptance.md)，不因保存方案改变语义。
- 替换成功后重查结果，并在影响当前页时载入新基线。刷新失败显示“修改已保存，刷新失败”，暂停可能覆盖新数据的编辑，只允许重试读取；不能重新执行替换来代替刷新。
- 结果不明的非幂等替换不得自动再次执行。先确认原生任务结果或通过版本与目标内容核对，不能把普通快照的重试方式直接套用到文本变换。
- 对文件有影响的换图、删除、导入和导出仍由图片与交换协议决策规定准备／提交／清理顺序；本契约定义进入操作前的保存与写入协调，不宣称 SQLite 能回滚文件副作用。

## 7. 单窗口与单写入者

- 同一应用数据目录同时只允许一个正常运行的应用进程；重复启动应聚焦已有窗口并结束第二实例，不再打开另一套可写界面。
- Tauri single-instance 插件按官方要求先注册，第二实例回调显式请求现有窗口恢复／聚焦；插件行为不能替代数据目录的排他保护。[官方插件说明](https://v2.tauri.app/plugin/single-instance/)
- 原生进程在迁移及开放业务前取得数据目录的进程级排他锁，持有至数据库和任务退出；不能仅靠“只创建一个窗口”证明没有另一个进程写库。
- 锁定失败不删除数据库或锁文件来强占运行状态；无法联系现有窗口时明确指出数据正被占用。锁的实际跨平台实现和异常退出释放行为纳入交付验证，不将一个文件存在就等同有效排他锁。
- 该保证约束遵守同一锁协议的本应用进程，不能宣称阻止任意外部程序直接写文件。候选文件锁实现须验证实际系统语义及最低版本兼容性。[Rust 文件锁语义](https://doc.rust-lang.org/std/fs/struct.File.html#method.try_lock)
- 活跃进程内部的内容写入用例统一串行协调，UI 的禁用按钮不是唯一保护；同一事务沿用 Orchestra Context，不能由另一连接绕过保存与批量操作的先后关系。
- 读取可以按事务保证取得一致状态，文件长任务不应为整个解码／导出时长占有数据库写事务。资源操作的具体提交时点由资源决策收束。

## 8. 行为验收

以下场景是必要验收依据：

| 场景 | 验证结果 |
| --- | --- |
| 连续输入与停止编辑 | 连续输入只重置一个定时器，停止 15 秒后发起一次；没有额外周期保存 |
| A 请求在途时继续输入 B | A 的回执只推进基线，B 仍保留且待保存 |
| 在途期间新增、删除或重排 | 草稿保持最新集合和顺序，不被旧快照还原 |
| 筛选后保存／整页确认校对 | 隐藏单元不被误删；全页操作范围不被筛选缩小 |
| 纯空白规范化与输入法组合 | 正确形成空态，不覆盖后续输入、不截断组合 |
| 重复触发保存和点击离开 | 没有并行快照写入，离开在保存确认后执行 |
| 失败、提交结果不明、提交后刷新失败 | 分别走留稿重试、确认结果、仅刷新路径，不重复变换文本 |
| 旧页面回执到达新页面 | 旧结果不能覆盖新会话 |
| 版本冲突与事务中途失败 | 保留草稿，库内没有部分写入或错乱序号 |
| 目标页加载失败 | 当前已保存页面可继续操作，工作位置不提前跳转 |
| 两次启动、原生关闭及平台退出 | 第二实例不成为写入者；正常退出执行保存协调 |
| 崩溃或强制终止后重开 | 恢复最近已提交内容，不承诺恢复内存草稿，不以正常退出结果代替 |
